landing: the missing screens

Companion to the phone prototype (mockups/index.html). It covers what the README lists as missing for Phase 0: the add/edit form, moving and reordering, empty, loading and error states, and the desktop grid. Same tokens and shapes as the prototype. Tiles now show the real URL and last-checked time instead of live service detail, which is Phase 2. The system and weather widgets are left out for the same reason. Amber tags mark spots that depend on an open question.

1 · desktop grid

The phone design stretched out: the tab bar becomes a top nav, the rows become tiles in an auto-fill grid (min 250px, so 2 to 5 per row as the window grows), and favorites become a strip. The whole tile is the link and opens the URL. The ⋯ button appears on hover or focus (always visible on touch) and opens edit, move and delete. This board is responsive, so narrow the window to watch the grid reflow.

2 · add & edit a bookmark

One form for add and edit. On phone it's a bottom sheet, opened from "+ add app" or a long-press on a tile. On desktop it's a centered modal, opened from "+ add bookmark" or the tile's ⋯ menu. Only name and URL are required. Paste a URL first and the name and favicon fill in by themselves. The group picker doubles as "move to group". With no login this is LAN-only, so anyone on the network can edit.

The ⋯ menu has quick versions of the most common edits, so the modal is only needed for real changes. "Move to ▸" lists the groups. Keyboard: Tab focuses a tile, Enter opens it, and the context-menu key (or Shift+F10) opens ⋯.

3 · arrange: reorder & move between groups

A separate "arrange" mode, so a normal tap never drags by accident. Turn it on from the pencil next to the title on phone, or the "arrange" button on desktop. Drag the handle to reorder within a group or drop into another group. Each group also gets ↑/↓ buttons so it works without dragging. Groups can be renamed or reordered here too.
